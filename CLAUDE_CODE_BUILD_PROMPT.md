Build a small public website that runs a long-term experiment: every 3 months it asks
Anthropic's latest frontier Claude model the same fixed prompt ("you are king of the
world, give your 1-year plan") and publishes the answer unedited, so readers can track
how the plan changes over time.

- edition-zero/seven-weeks-as-king.html    the original one-off answer (different question,

                                           origin of the experiment. Keep it out of the timeline.

BEFORE WRITING CODE
- Read the current Anthropic API docs at https://docs.claude.com for: the Messages API,
  the server-side web search tool, structured/JSON output, and current model IDs. Do not
  rely on memory for model IDs, tool names or parameters. I expect the model to be
  claude-fable-5-2; confirm it exists and is available on my key, and tell me if not.
- Ask me for: the repo name, GitHub owner, public or private, and the domain. Do not
  create the remote repo, push, or touch DNS until I confirm.

STORAGE: NO DATABASE
- The git repo is the database. Each edition is one committed file.
- /prompt/king.md        the fixed prompt, verbatim. Never edited after launch.
- /config.json           { "model": "<id>", "max_searches": <n>, "cadence_months": 3 }
- /editions/YYYY-MM-DD.json       the validated edition
- /editions/raw/YYYY-MM-DD.json   the full raw API response, untouched
- /schema/edition.schema.json     JSON Schema for an edition

RUNNER (scripts/run-edition)
- Reads /prompt/king.md and sends it as the user message, byte for byte.
- Sends the run date only in the system message: "Today's date is YYYY-MM-DD."
  Nothing else goes in the system message. No previous editions are ever sent.
- Enables web search. Requests JSON matching the schema.
- Adds metadata to the saved edition: run date, model ID returned by the API,
  SHA-256 of king.md, token usage, number of searches.
- Validates against the schema. If validation fails, retry once. If it fails again,
  save the raw response, publish nothing, and open a GitHub issue.
- Never edits, trims or "fixes" the model's content. Publish verbatim or not at all.
- Has a --dry-run flag that writes to a temp folder and commits nothing.

SCHEDULE
- GitHub Actions workflow, cron on the 1st of January, April, July and October,
  plus manual workflow_dispatch. It runs the runner and commits the new edition.
- ANTHROPIC_API_KEY lives only in GitHub Actions secrets. Never in the repo, logs,
  or the client bundle. Add a check that fails CI if a key pattern is committed.
- Vercel deploys on push to main.

SITE
- Static site (use Astro unless you find a concrete reason not to; tell me if so).
  No client-side API calls. Responsive, fast, readable long-form typography,
  light and dark mode that follows the system setting with a manual toggle.
- Home: the latest edition in full, with edition date and model shown at the top.
- /editions: a timeline of every edition.
- /editions/[date]: one edition, with numbered sources as links.
- /compare: pick two editions and see what changed: decrees added, dropped or
  reworded, budget changes, and the ten indicators side by side.
- /indicators: one small chart per indicator across all editions.
- /method: the full prompt text, its hash, the schema, the schedule, the model
  history, and a link to the repo. State plainly that nothing is edited by a human.
- Every page footer: "An independent experiment. Not affiliated with or endorsed by
  Anthropic. Generated by an AI model as a thought experiment. Not advice."
- Mark any figure the model flagged as unverified so it is visually distinct.

QUALITY

- When done: do one --dry-run, show me the output, and wait for my go-ahead before
